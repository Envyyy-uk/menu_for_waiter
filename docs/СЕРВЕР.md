# Сервер: что брать и как поставить

Коротко: **Hetzner Cloud, тариф CX42, Хельсинки или Фалькенштайн, с включёнными
бэкапами — около €21 + €4 в месяц.** Это примерно $28 и запас раз в двадцать
больше, чем нужно этому проекту.

Ниже — почему именно так, что ещё понадобится и чего облако не умеет.

---

## Сколько на самом деле надо

Считаем не на глаз. В тяжёлый вечер:

| Что | Сколько |
|---|---|
| Устройств онлайн (телефоны + планшеты) | 10–15 |
| Открытых сокетов | по одному на устройство |
| Заказов за вечер | 200–400 |
| Запросов к базе на заказ | десятки, все крошечные |
| Рост базы | единицы мегабайт в месяц |

Это нагрузка уровня «домашний роутер справится». Тяжёлого здесь нет ничего:
ни картинок, ни видео, ни отчётов на миллион строк. Узкое место в таком
приложении — не процессор, а обрыв связи в зале.

Поэтому вопрос не «хватит ли мощности», а «не придётся ли к нему возвращаться».
Отсюда и выбор: берём заведомо с запасом, чтобы забыть.

## Что брать

### Рекомендация — Hetzner Cloud CX42

**8 vCPU, 16 ГБ RAM, 160 ГБ NVMe, 20 ТБ трафика — около €21/мес** плюс €4 за
автоматические бэкапы. Итого ≈ €25 ≈ $28.

Почему он:

* **Запас в двадцать раз.** Проекту хватит и CX22 за ~€5. CX42 берётся не ради
  скорости, а чтобы никогда не упереться: одновременно поместятся база, сервер,
  бэкапы и вторая копия для проверок.
* **Панель, из которой видно всё.** Консоль прямо в браузере — если сломается
  сеть или ssh, машина всё равно доступна. Снимок диска делается одной кнопкой
  перед любым изменением; не понравилось — откат за минуту.
* **Бэкапы включаются галочкой** (+20% к цене) и снимаются каждую ночь.
* **20 ТБ трафика** — столько это приложение не наберёт и за десять лет.
* Дата-центр в Хельсинки или Фалькенштайне: до Британии 25–35 мс. Для нажатия
  «Отправить» это незаметно.

**Важно про цены.** В июне 2026 Hetzner поднял цены, и очень неравномерно:
линейки CPX и CCX подорожали на 113–175% (CCX13 стал €42.99 вместо €15.99,
CPX41 — €120.49 вместо €38.99), а линейка **CX выросла всего на ~30%**. Поэтому
берите именно CX. Цифры выше — на август 2026; перед оплатой сверьтесь с
прайсом, они снова могли поехать.

### Если хочется дешевле или дороже

| Вариант | Цена | Когда брать |
|---|---|---|
| Hetzner **CX22** (2 vCPU, 4 ГБ) | ≈ €5 | Хватит с головой. Берите, если хочется тратить минимум |
| Hetzner **CX32** (4 vCPU, 8 ГБ) | ≈ €9 | Разумный минимум с запасом |
| Hetzner **CX42** (8 vCPU, 16 ГБ) | ≈ €21 | **Рекомендация** |
| Hetzner **CX52** (16 vCPU, 32 ГБ) | ≈ €41 | «Не хочу об этом думать никогда» |
| **netcup** RS/VPS G12 | от €10 | Дешевле за те же ресурсы, немецкий хостер. Панель проще, почасовой оплаты нет |

### На один-два дня, чтобы просто попробовать

Отдельный вопрос: не «на чём работать», а «на чём проверить». Здесь дорогой
тариф не нужен вовсе, а важно другое — **почасовая оплата**.

**Берите Hetzner Cloud CX22 и удалите его после проверки.** Hetzner считает
по часам: CX22 стоит ≈ €0.007 в час, значит двое суток — **меньше €0.50**, с
IPv4-адресом вместе. Месячная цена — это просто потолок, до которого счёт не
дойдёт. CX22 для проверки не «слабый вариант»: этому приложению его хватает и
для настоящей работы, а разницу с CX42 вы на трёх устройствах не увидите.

Если хочется проверить ровно ту машину, на которой будете работать, возьмите
CX42 — двое суток выйдут около €1.40. Это дешевле чашки кофе, и торговаться
здесь не о чем.

> **Главная ловушка почасовой оплаты: выключенный сервер продолжает считаться.**
> Hetzner берёт деньги за существование машины, а не за её работу. «Выключить»
> — недостаточно, нужно **удалить** (Delete), и вместе с ним снимки (Snapshots)
> и отдельные IP (Floating IPs), если создавали. Проверьте это на следующий
> день: пустой счёт лучше догадок.

**Что делать с HTTPS на два дня.** Домен за £10 ради проверки покупать не
обязательно: поднимите на сервере тот же туннель, что и дома, и получите
рабочий https-адрес бесплатно (`docs/ДОМА.md`, раздел про Cloudflare). Для
проверки этого достаточно — заработают и установка на домашний экран, и push.
Для настоящей работы туннель не годится: адрес временный и меняется.

**А может, и покупать не надо.** Если проверить нужно только «как это
выглядит с телефонов по мобильному интернету», сервер не нужен вообще: тот же
туннель поднимается к докеру на вашем ноутбуке, и приложение открывается
откуда угодно. Сервер стоит брать, когда нужна проверка **без вашего
ноутбука**: планшеты работают всю смену, а вы ушли домой.

**Чего брать не стоит.** Contabo — заметно дешевле, но производительность
плавает от соседей по железу; для кассы в вечер пятницы это плохая лотерея.
AWS, Google Cloud, Azure — тот же сервер выйдет втрое дороже, а платить придётся
за сложность, которая здесь не нужна.

## Что ещё понадобится

| Что | Сколько | Зачем |
|---|---|---|
| IPv4-адрес | ~€0.60/мес | Отдельной строкой в корзине; без него не подключиться |
| Домен | ~£10/год | Без него не будет HTTPS |
| HTTPS-сертификат | бесплатно | Caddy получает Let's Encrypt сам |
| Бэкапы Hetzner | +20% к серверу | Снимок всей машины каждую ночь |
| Резервный 4G-роутер | £30 + тариф | См. ниже |

**HTTPS обязателен.** Без него не работает Web Push (уведомления при свёрнутом
приложении) и приложения не ставятся на домашний экран. Домен + Caddy закрывают
это в две строки конфига.

## Откуда приложение открывается

Сервер в облаке — значит **из любой сети**: с мобильного интернета, из дома,
из отпуска. Wi-Fi нужен только в домашней проверке, где сервером работает
ноутбук в той же комнате; с настоящим сервером такой привязки нет.

* **Телефон официанта по 4G работает так же**, как по Wi-Fi. Трафика уходит
  мало: смена целиком — единицы мегабайт, это меньше одной фотографии.
* **Планшеты станций лучше держать на Wi-Fi.** Не из-за трафика, а потому что
  они стоят на месте и не должны зависеть от заряда мобильного модема.
* **Владелец смотрит отчёты откуда угодно** — админка открывается тем же
  адресом с любого телефона.

И полезное следствие: **телефон на мобильном интернете не зависит от Wi-Fi
заведения**. Упал роутер в баре — планшеты станций встали, а телефоны
официантов продолжают работать: сервер не в подсобке, а в дата-центре. Это
не заменяет резервный роутер, но вечер спасает.

**Обратная сторона: адрес доступен всем.** Кто знает домен, тот увидит экран
ввода PIN. Поэтому:

* PIN блокируется после пяти неверных попыток — и по устройству, и по адресу
  в сети, чтобы подбор не шёл с одного компьютера в цикле;
* вход в админку — шесть цифр, миллион вариантов вместо десяти тысяч;
* адрес не нужно печатать на видном месте и раздавать гостям: он не секрет,
  но и не реклама.

## Чего облако не умеет — и что с этим делать

**Упал интернет в заведении — встал POS.** Сервер в облаке доступен ровно
настолько, насколько работает связь на месте. Это не недостаток Hetzner, это
свойство любого облака.

Что с этим делают:

1. **Резервный 4G-роутер** с автоматическим переключением. Дешевле и проще
   всего; связь падает на секунды, а не на вечер.
2. **Мини-ПК в заведении** как основной сервер, облако — для отчётов и бэкапов.
   Тогда зал работает даже без интернета вообще. Дороже в настройке, но для
   кассы это правильный путь, если сбои случаются регулярно.

Начните с первого. Если за пару месяцев связь подвела больше раза — переезжайте
на второй, приложение от этого не меняется: тот же `docker compose`.

**«Работать вечно» сервер не будет.** Раз в пару месяцев нужны обновления
системы, иначе через год он превращается в дыру. Ниже это сведено к двум
командам и одному автоматическому обновлению.

## Как поставить

Всё нужное лежит в `deploy/`. По шагам:

### 1. Сервер

Создайте CX42 в Hetzner Cloud: Ubuntu 24.04, добавьте свой SSH-ключ, включите
бэкапы. Запишите IP.

### 2. Домен

У регистратора добавьте `A`-запись на IP сервера. Например
`pos.вашезаведение.com`.

### 3. Первая настройка

```bash
ssh root@IP

# Обновления безопасности ставятся сами — без этого сервер стареет опасно.
apt update && apt upgrade -y
apt install -y docker.io docker-compose-v2 git ufw unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades

# Наружу открыто только то, что нужно: ssh и веб.
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
```

### 4. Приложение

```bash
git clone https://github.com/Envyyy-uk/menu_for_waiter.git /srv/pos
cd /srv/pos
cp .env.example .env
nano .env          # SECRET_KEY, SEED_ADMIN_PIN, PUBLIC_BASE_URL, VAPID-ключи
```

В `.env` обязательно поменять:

* `SECRET_KEY` — случайная строка от 32 символов (`openssl rand -hex 32`);
* `SEED_ADMIN_PIN` — четыре цифры, которыми вы войдёте первый раз;
* `PUBLIC_BASE_URL=https://pos.вашезаведение.com`;
* `POS_DOMAIN=pos.вашезаведение.com` — его читает Caddy;
* `VAPID_*` — ключи для push: `docker compose run --rm api python -m app.tools.vapid`.

Поднять:

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml up -d --build
```

Через минуту `https://pos.вашезаведение.com` отвечает, сертификат выписан сам.

### 5. Бэкапы базы

Снимок всей машины у Hetzner — раз в сутки. Этого мало для кассы: между
снимками теряется целый вечер. Поэтому база выгружается отдельно, каждый час:

```bash
crontab -e
# каждый час, хранить 14 дней
0 * * * * /srv/pos/deploy/backup.sh >> /var/log/pos-backup.log 2>&1
```

## Что делать дальше

**Посмотреть, что происходит:**

```bash
docker compose --env-file .env -f deploy/docker-compose.prod.yml logs -f api
```

**Обновить приложение:**

```bash
cd /srv/pos && git pull
docker compose --env-file .env -f deploy/docker-compose.prod.yml up -d --build
```

Перед обновлением сделайте снимок диска в панели Hetzner — откат тогда стоит
одну минуту.

**Обновить систему:** раз в пару месяцев `apt update && apt upgrade -y` и
перезагрузка. Всё остальное ставится само.

**Восстановиться из бэкапа:**

```bash
gunzip -c /srv/pos/backups/pos-2026-08-20-14.sql.gz | \
  docker compose --env-file .env -f deploy/docker-compose.prod.yml exec -T db psql -U pos pos
```
