# Запустить дома и потрогать с телефона и планшета

Смысл домашнего прогона один: увидеть, как заказ с телефона появляется на
планшете, и услышать сигнал «готово». Сервер для этого не нужен — хватит
ноутбука и домашнего Wi-Fi.

Всё, что ниже, проверено: приложение открывается с любого устройства в той же
сети, вход работает, марки приезжают сами.

---

## Что понадобится

* Ноутбук или компьютер — Windows, macOS или Linux;
* **Docker Desktop** ([docker.com](https://www.docker.com/products/docker-desktop/)) —
  ставится один раз, дальше всё одной командой;
* телефон и планшет **в той же сети Wi-Fi**, что и ноутбук.

Никаких доменов, сертификатов и оплаты сервера для этого не нужно.

## 1. Поднять

```bash
git clone https://github.com/Envyyy-uk/menu_for_waiter.git
cd menu_for_waiter
cp .env.example .env
docker compose up --build
```

Первый запуск идёт пару минут: скачивается Postgres, накатываются миграции,
заливается меню и двенадцать столов. Когда в логе появится

```
INFO  меню: 45 позиций, столов добавлено: 12
WARNING создан владелец «Владелец», PIN — 123456
```

— всё готово. Этим PIN вы войдёте в админку первый раз.

Окно с логом не закрывайте: пока оно открыто, POS работает. Остановить —
`Ctrl+C`.

## 2. Узнать адрес ноутбука

Телефон должен знать, куда стучаться. Адрес вида `192.168.…`:

| Система | Команда |
|---|---|
| Windows | `ipconfig` → строка **IPv4-адрес** |
| macOS | `ipconfig getifaddr en0` (Wi-Fi) |
| Linux | `hostname -I` |

Допустим, получилось `192.168.1.50`.

**Впишите его в `.env`** — одна строка:

```
PUBLIC_BASE_URL=http://192.168.1.50:8000
```

и перезапустите: `Ctrl+C`, затем `docker compose up`.

> **Схема важна.** Оставьте `http://`, а не `https://`. По https сессионная
> cookie помечается флагом Secure и по обычному http уже не доедет — вход
> просто перестанет работать, без внятной ошибки.

### Если Docker запущен в WSL (Windows)

Отдельный случай, на котором теряют вечер. WSL — это не «Linux внутри
Windows», а отдельная маленькая виртуальная машина со своим адресом. Windows
сама пробрасывает в неё `localhost`, поэтому **с самого ноутбука откроется, а
с телефона — нет**: для телефона `192.168.…` — это Windows, а порт слушает
WSL.

Сначала посмотрите, чем вы запускаете:

```bash
docker context ls        # видно, какой контекст активен
```

* **Docker Desktop** (в списке есть `desktop-linux`) — ничего делать не надо:
  он публикует порты на самой Windows, и телефон достучится. Останется только
  разрешить порт в брандмауэре, когда Windows спросит.
* **Docker внутри WSL** (`apt install docker.io` в самой Ubuntu) — порт
  остался в виртуальной машине. Два выхода:

**Проще (Windows 11).** Сказать WSL работать в сети ноутбука напрямую.
В блокноте создайте файл `C:\Users\ВАШЕ_ИМЯ\.wslconfig`:

```ini
[wsl2]
networkingMode=mirrored
```

Затем в PowerShell `wsl --shutdown`, откройте WSL заново и запустите
`docker compose up`. Теперь адрес ноутбука и адрес WSL — один и тот же.

**Надёжнее (работает везде).** Пробросить порт руками. В WSL узнайте его
адрес — `hostname -I` (что-то вроде `172.20.10.3`), затем в PowerShell
**от администратора**:

```powershell
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8000 `
  connectaddress=АДРЕС_ИЗ_WSL connectport=8000
New-NetFirewallRule -DisplayName "POS 8000" -Direction Inbound `
  -LocalPort 8000 -Protocol TCP -Action Allow
```

Минус: адрес WSL меняется после перезагрузки, и проброс придётся повторить.
Убрать потом:
`netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8000`.

> **`nano .env` не создаёт настройки, а создаёт пустой файл.** Если `.env` ещё
> нет, nano молча откроет пустоту, и сохранённый пустой файл выглядит как
> «настроил». Сначала `cp .env.example .env`, и только потом правьте.

## 3. Пустить телефон и планшет

На каждом устройстве откройте в браузере:

```
http://192.168.1.50:8000
```

| Адрес | Кто открывает |
|---|---|
| `http://192.168.1.50:8000/` | телефон официанта |
| `http://192.168.1.50:8000/station/` | планшет бара или кухни |
| `http://192.168.1.50:8000/admin/` | админка (шесть цифр) |

**Если не открывается** — почти всегда брандмауэр ноутбука. Windows при первом
запуске спрашивает разрешение: нужно разрешить для **частных сетей**. Если
спросил и вы нажали «нет» — Параметры → Сеть → Брандмауэр → разрешить порт
8000. На macOS: Системные настройки → Сеть → Брандмауэр → разрешить Docker.

## 4. Завести смену

Сидер создаёт только владельца: заведению не нужен персонал с заранее
известными PIN-ами. Остальных заводите в админке.

1. Откройте `/admin/`, войдите PIN-ом из лога (`123456`).
2. **Персонал** → впишите имя, выберите роль, «Завести сотрудника». PIN
   покажется один раз — запишите. В зале он из четырёх цифр, в админке из
   шести.
3. **Станции** → задайте PIN планшета бара и кухни. Им открывают смену на
   планшете, и им же её закрывают.
4. На телефоне войдите PIN-ом официанта, на планшете — PIN-ом станции.

Для быстрой пробы всю смену можно завести одной командой — официант, бармен,
кухня и менеджер с простыми PIN-ами:

```bash
python3 tools/dev_staff.py http://192.168.1.50:8000
```

## 5. Что проверять

Ради чего всё и затевалось:

1. Официант открывает стол, набирает заказ, нажимает **Отправить**.
2. Марка **сама** появляется на планшете — ничего не обновляя.
3. Бармен нажимает **Принял**, потом **Готово**.
4. На телефоне официанта звучит сигнал и появляется полоса «готово».
5. **Выключите на телефоне звонок и повторите.** Сигнал всё равно слышно:
   он идёт по медиаканалу, как музыка, а не как уведомление.
6. Закройте чек картой или наличными. Загляните в админку → **Оплаты**.

Дальше — то, что ломается в жизни: выключите Wi-Fi на планшете. Через десять
секунд экран честно скажет, что связи нет. Включите обратно — марки
доедут сами.

## Что дома работает не всё

По локальной сети приложение открывается по `http`, а браузеры считают такой
адрес незащищённым. Два следствия:

* **Приложение не поставится на домашний экран** — открывается вкладкой в
  браузере. Работает при этом всё.
* **Не будет push** — уведомлений, когда приложение свёрнуто. Сигнал «готово»
  при открытом приложении работает, а он и есть основной путь.

Остальное — столы, чеки, марки, звук, склад, оплаты — работает полностью.

### Если хочется проверить и установку на экран

Нужен адрес по `https`. Дома проще всего временным туннелем: он выдаёт
настоящий https-адрес, не требуя ни домена, ни настроек роутера.

```bash
# в отдельном окне, пока docker compose работает
cloudflared tunnel --url http://localhost:8000
```

Команда напечатает адрес вида `https://random-words.trycloudflare.com`.
Впишите **его** в `.env` как `PUBLIC_BASE_URL`, перезапустите
`docker compose` — и открывайте этот адрес на телефоне. Теперь приложение
ставится на домашний экран, а если задать VAPID-ключи, заработает и push.

Туннель живёт, пока открыто окно, и адрес каждый раз новый. Для боевой
работы это не годится — там нужен свой сервер и домен, см. `docs/СЕРВЕР.md`.

## Мелочи, которые экономят вечер

* **Ноутбук не должен засыпать.** Уснул — POS выключился. На время проверки
  поставьте «не переходить в спящий режим при питании от сети».
* **Адрес меняется.** Роутер выдаёт ноутбуку адрес заново; если утром
  перестало открываться — посмотрите IP ещё раз (шаг 2).
* **Начать с чистого листа:** `docker compose down -v` — стирает базу вместе
  с чеками и персоналом, следующий запуск заведёт всё заново.
* **Просто выключить:** `docker compose down` — данные останутся.
* **Посмотреть, что происходит:** `docker compose logs -f api`.
* **Меню приезжает с сайта** каждые пять минут. Если дома нет интернета,
  POS работает по тому меню, что уже скачал, и пишет об этом в админке.
